피드백 상세 페이지(Detail Page)의 UI를 컴포넌트 단위로 분할하여 모듈화하는 과정과 API 호출 결과가 State에 즉각 저장되지 않는 비동기 오류 해결 방법을 다룬다.

## 1. 상세 페이지 구조 설계 및 컴포넌트 분할
계층 구조가 깊은 상세 페이지를 깔끔하게 유지하기 위해 컴포넌트 구조를 체계화했다.
- **Header**: 이전 페이지 복귀 버튼 및 피드백 수정 버튼 배치
- **Main**: 피드백 본문 카드 + 댓글 컨테이너
- **Comments Container**: 댓글 목록(`CommentList`), 개별 댓글 아이템(`CommentItem`), 답글 목록(`RepliesList`), 답글 작성 폼(`NewReplyForm`)을 하위 노드로 계층화

## 2. 해상도별 댓글 컴포넌트 구조 최적화
모바일과 데스크탑 화면에서 프로필 이미지, 유저 정보, 답글 버튼의 위치가 달라지는 문제를 해결하기 위해 미디어 쿼리를 세분화했다.
- **모바일**: 상단에 헤더 정보와 답글 버튼을 한 행으로 배치하고 본문을 하단에 표시
- **데스크탑**: 좌측에 유저 정보 영역을 확보하고 본문 우측 여백(Margin)을 고정하여 레이아웃을 시각적으로 안정시킴

## 3. Fetch 비동기 데이터 전달 및 State 업데이트 버그 해결
- **문제**: API 호출(`fetch`)을 통해 데이터를 불러와 `setState`에 담아 렌더링을 시도했으나, 데이터가 할당되기 전에 렌더링 로직이 먼저 실행되어 값이 화면에 바인딩되지 않고 빈 화면이 지속되는 에러가 발생했다.
- **해결**: JavaScript의 비제어적 비동기 처리가 원인이었다. Promise 내부 흐름에서 데이터 응답이 확인된 후에 로딩 상태(`isLoading`)를 해제하도록 처리 순서를 조정했다. 이후 코드 가독성과 신뢰성을 위해 비동기 흐름 제어를 `async/await` 방식으로 마이그레이션했다.
