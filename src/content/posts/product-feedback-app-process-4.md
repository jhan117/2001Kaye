피드백의 신규 등록(New Feedback)과 수정(Edit Feedback)은 핵심 필드가 유사하므로, 하나의 `<FeedbackForm />` 공용 컴포넌트를 설계하여 중복 코드를 제거했다. 또한 수정 데이터 반영이 지연되어 이전 데이터가 화면에 노출되는 현상의 디버깅 과정을 다룬다.

## 1. 생성/수정 공용 `<FeedbackForm />` 설계
하나의 컴포넌트 내부에서 생성 모드와 수정 모드를 동적으로 처리할 수 있도록 폼 컴포넌트 단위를 아래와 같이 세분화하고 모듈화했다.
- **공통 폼 구조**: 제목 입력(`InputForm`), 카테고리 선택(`SelectForm`), 본문 작성(`TextareaForm`)
- **수정(Edit) 모드 조건부 렌더링**: 수정 모드일 때만 상태값 설정창(`SelectForm`)과 삭제 버튼(`DeleteBtn`)이 하단 영역에 노출되도록 제어

## 2. 데이터 업데이트 후 직전 데이터가 로딩되던 이슈 해결
- **문제**: 피드백 내용을 수정한 직후 상세 페이지로 리다이렉트되었을 때, 수정 데이터가 적용되지 않은 '수정 전의 데이터'가 지속적으로 먼저 불러와지는 현상이 발생했다. Firebase 서버에 데이터가 완전히 반영되는 처리 과정에서 미세한 지연 시간(Network Latency)이 발생하기 때문이었다.
- **해결**: 수정 처리가 완료되었는지 안전하게 확인하고 상세 화면을 보여주어야 했다. 그렇다고 너무 많은 무작정 재호출(Polling) API 트래픽을 방출할 수는 없었다. 
  - `setInterval` 타이머를 사용해 500ms(0.5초) 간격으로 데이터가 업데이트되었는지 체크했다.
  - 데이터 업데이트가 성공했음이 검증되는 즉시 `clearInterval`로 타이머를 안전하게 취소하고 새 데이터를 주입하도록 개선했다.
