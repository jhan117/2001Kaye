기기별 해상도 대응을 고려하지 않은 채 마구잡이로 작성했던 기존 레이아웃을 완전히 파악하고, 모바일 우선(Mobile-first) 구조로 재구성하는 과정과 Firebase 연동 후 발생한 상태 렌더링 이슈의 해결 과정을 정리한다.

## 1. 반응형 기획 및 컴포넌트 재구성
모바일 해상도에서 태블릿/데스크탑 해상도로 이동할 때 구조가 완전히 달라지는 보드(Board), 카테고리(Category), 로드맵(Roadmap) 레이아웃의 컴포넌트 구조를 기획한 후 구현했다.
- **모바일**: 상단 가로형 보드 + 햄버거 메뉴 모달 내 세로형 카테고리/로드맵
- **태블릿**: 가로 정렬의 Flex 레이아웃
- **데스크탑**: 좌측 세로 배치 레이아웃

## 2. 정렬 및 필터링 업데이트 지연 버그 해결
- **문제**: 카테고리 필터나 정렬 기준(Sort By)을 클릭했을 때 리스트가 즉시 갱신되지 않고, 직전에 누른 조건값으로 한 단계씩 지연되어 정렬되는 현상이 발생했다. 
- **해결**: `useEffect` 훅의 실행 우선순위 문제로 파악되어, 데이터를 불러오는 즉시 필터링(filter)이 작동하게 구조를 개선했다. 정렬(sort) 함수 내부에서 카테고리 변경 상태(tag) 처리를 단일 스레드로 묶어서 처리하고 데이터 동기화를 완료했다.

## 3. Firebase PATCH 연동 및 실시간 렌더링 버그 해결
- **문제**: Firebase에 PATCH 요청을 보내 DB의 추천이나 내용을 직접 수정한 후, 프론트엔드 화면에 변경사항이 렌더링(Rendering) 되지 않았다. 그렇다고 단순 Get 훅의 의존성 배열에 응답 데이터를 무작정 추가하면 무한 리로드 루프가 걸리는 부작용이 발생했다.
- **해결**: 데이터 업데이트 시 무한 갱신되는 위험을 회피하기 위해 `setInterval` 폴링 방식을 활용해 적절한 간격(Interval)으로 API 호출을 제어하는 단기 임시 대책을 적용했다.

## 4. CSS 팁
Flex와 Grid 환경에서 자식 요소 중 하나만 개별적으로 축 정렬을 다르게 지정해야 할 경우 `align-self` 속성을 활용해 유연하게 수직 정렬을 제어했다.
