기존 Firebase DB에 이상한 데이터가 섞여 문제가 생겼음을 알고 있었으나 방치하고 있었다. 최근 블로그를 수정하며 프론트엔드 작업을 다시 시작했고, 생각난 김에 DB 문제를 해결하며 기존 코드의 문제점들을 함께 고쳤다.

## 1. Firebase DB 구조 개선 및 타입 안전성 확보
### Firebase DB 구조 개선 (Array Leakage 해결 및 평탄화)
- **문제**: Firebase RTDB는 키가 순차적인 숫자(`0, 1, 2...`)일 경우 객체가 아닌 배열로 강제 변환하여 데이터를 반환하는 특성이 있다. 이로 인해 클라이언트에서 데이터를 가져와 파싱할 때 에러가 발생했다. 또한 사용자 추천 데이터(`upvoteItems`)가 `{"2": {"sugId": 2}}` 형태의 불필요하게 중첩된 객체 구조로 이루어져 있었다.
- **해결**: 
  - 피드백 및 댓글 식별자를 순차적인 숫자 대신 `crypto.randomUUID()` 문자열로 전면 교체하여 Firebase의 배열 자동 변환 현상을 원천 방지했다.
  - 추천 데이터를 `Record<string, boolean>` 형태의 평탄화(Flat) 객체(`{"uuid": true}`)로 변경하여 읽기/쓰기 성능을 향상시키고 API 요청 페이로드를 단순화했다.
  - 타입 지정을 업데이트하여 `id`를 `string`으로, `upvoteItems`를 `Record<string, boolean>` 타입으로 변경하여 타입 안전성을 확보하고 컴포넌트 내 불필요한 `Number(id)` 파싱 코드를 모두 제거했다.

## 2. 렌더링 성능 최적화
### 비제어 컴포넌트(Uncontrolled Components) 도입
- **문제**: 제어 컴포넌트 방식을 사용하여 사용자가 폼에 한 글자 입력할 때마다 입력 폼 전체와 부모 컴포넌트가 불필요하게 재렌더링되었다.
- **해결**: 입력 폼에 연결되어 있던 로컬 State를 제거하고 비제어 컴포넌트 방식으로 전환했다. 폼 제출(Submit) 시점에 `FormData` 객체를 통해 입력값을 한 번에 추출하고 유효성을 검증하게 함으로써 입력 시 렌더링 부하를 줄였다.

### 불필요한 React State 조작을 제거하고 CSS Selector 활용
- **문제**: 마우스 호버(Hover) 효과를 주기 위해 React State를 조작하는 불필요한 JS 핸들러가 컴포넌트 내부에 존재하여 마우스를 움직일 때마다 컴포넌트가 재렌더링되는 비효율이 발생했다.
- **해결**: JS 호버 상태 핸들러를 걷어내고 순수 CSS의 `:hover` 선택자를 사용하여 스타일을 적용해 렌더링 성능을 개선했다.

## 3. 사용자 경험(UX) 및 인터랙션 개선
### Optimistic UI 및 Rollback 패턴 구현
- **문제**: 추천(Upvote), 댓글 작성, 피드백 생성/수정/삭제 등의 CRUD 작업 시 서버 응답을 대기한 후 UI를 업데이트하여 사용자 피드백이 느렸다.
- **해결**: Redux Thunk 요청 시 `.pending` 단계에서 로컬 상태를 선제적으로 즉시 업데이트하고, API 요청이 실패할 경우 `.rejected`에서 `action.meta.arg`를 전달받아 원래 상태로 롤백하는 구조를 구현했다.

### URL Query Parameter 보존 및 필터 유지
- **문제**: 피드백 상세 페이지에 진입한 후 뒤로 돌아오면 이전에 설정해둔 카테고리 필터와 정렬 기준이 초기화되는 사용성 문제가 있었다.
- **해결**: 카테고리 필터 및 정렬 상태를 URL Query Parameter(`?sort=...&category=...`)로 관리하도록 개선하여, 이전 페이지로 복귀해도 필터 상태가 정상적으로 유지되도록 했다.

### 히스토리 스택(History Stack)을 고려한 스마트 라우팅 및 안전장치
- **문제**: 글 수정/삭제 후 단순히 `navigate(-1)` 처리를 했을 때, 브라우저 뒤로 가기를 누르면 삭제된 페이지를 조회하려 시도하거나 이전 편집 페이지로 다시 돌아오는 등 무한 루프가 발생하는 오류가 있었다.
- **해결**: 
  - 피드백 삭제 시 `navigate(-2)`를 활용해 상세 페이지와 수정 페이지를 스택에서 동시에 제거하고, 글 상태(status)에 맞춰 홈 또는 로드맵 페이지로 적절히 분기 처리하도록 리다이렉트 로직을 변경했다.
  - 새로고침이나 다이렉트 진입 등으로 브라우저 방문 기록이 존재하지 않을 때 'Go Back' 버튼이 비활성화되거나 동작하지 않는 현상을 해결하기 위해 `window.history.state.idx`를 감지하여 루트(`/`) 경로로 이동시키는 안전장치를 추가했다.

### 댓글 단축키 및 자동 스크롤(Smooth Scroll) 지원
- **문제**: 댓글 작성 완료 버튼을 마우스로 클릭해야만 작성이 완료되어 타이핑 중 조작 흐름이 끊겼다.
- **해결**: 
  - 댓글 입력 창에서 `Enter` 키를 입력하면 즉시 제출(Submit)이 되고, 줄 바꿈은 `Shift + Enter`로 작동하도록 키보드 단축키를 추가했다.
  - 댓글 등록이 완료되면 댓글 리스트 하단으로 자동으로 부드럽게 스크롤(Smooth Scroll)하는 인터랙션을 추가했다.

## 4. 디자인 및 UI 일관성 정돈
### 게스트 로그인 페이지 디자인 단순화
- **문제**: 로그인 페이지의 그라데이션, 글래스모피즘, 화려한 슬라이드 애니메이션 등이 앱 전체의 정적이고 미니멀한 디자인 테마와 어울리지 않았다.
- **해결**: 화려한 애니메이션과 그라데이션을 걷어내고 솔리드한 색상 톤과 일관성 있는 레이아웃의 단정한 테마로 변경했다.

### 유저 프로필 이미지 동적 연동
- **문제**: 우측 상단 헤더의 유저 프로필 아바타가 DB 정보와 상관없이 하드코딩된 'G' 아바타 이미지로 고정되어 있었다.
- **해결**: DB에 등록된 현재 로그인한 유저의 프로필 이미지 주소(`currentUser.image`)를 동적으로 받아와 헤더 아바타에 연동했다.

### 레이아웃 흔들림(Layout Shift) 방지 및 애니메이션 품질 향상
- **문제**: 페이지에 스크롤이 생기거나 사라질 때 전체 레이아웃이 좌우로 흔들리는 문제가 존재했고, 선택창(Select)의 화살표 모션이 뚝뚝 끊기는 한계가 있었다.
- **해결**: 
  - 스크롤 영역을 안정적으로 고정하여 레이아웃 시프트를 미연에 방지했다.
  - 선택창 열림/닫힘 시 화살표 아이콘 회전 모션에 `Cubic-bezier` 기반의 자연스러운 전환 애니메이션을 추가하여 움직임을 매끄럽게 개선했다.

### 데스크탑 해상도 및 모바일 반응형 CSS 구조 개선
- **문제**: 데스크탑 고해상도 및 모바일 기기의 특정 해상도에서 레이아웃이 비정상적으로 찌그러지거나 깨지는 현상이 발생했다.
- **해결**: 컨테이너의 고정 너비와 패딩 구조를 반응형 미디어 쿼리에 맞추어 전반적인 레이아웃을 다시 보정했다.

## 5. 배포 및 빌드 최적화
### Vercel 배포 빌드 규격(ESLint 규칙) 준수
- **문제**: 미사용 변수 및 무의미한 Import 등 빌드 시점에 ESLint 경고 및 오류가 발생하는 상태여서 Vercel 배포 파이프라인에서 빌드가 차단되었다.
- **해결**: 코드 내 사용하지 않는 변수와 모듈 임포트를 말끔히 제거하고 빌드 오류를 차단하여 Vercel을 이용한 실시간 빌드 및 배포 안정화를 완료했다.
